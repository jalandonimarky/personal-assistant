Ingest

How a pasted meeting, thread, deck, or decision becomes a structured file in an assistant’s knowledge base — and why the file’s kind decides whether it may create commitments.

1 · What it actually is

Ingest is a template inserter. Pressing the button writes a filing instruction into the message box. That is the entire mechanism — there is no hidden prompt, no background call, and nothing is sent until you press Send.

The instruction is visible and editable. You can rewrite it, or delete it and type your own; it carries no special status once it is in the box.

  1. Switch the mode selector to Authoring. It is the only mode whose --allowedTools includes Write and Edit, so it is the only mode that can produce a file at all.
  2. Choose what you are pasting, or leave the selector on Auto-detect.
  3. Press Ingest →. The instruction appears with the cursor parked at the end.
  4. Paste your raw material underneath it, and Send.

The assistant writes the file, then opens its reply by naming where it filed it and why, followed by what is new, what contradicts what it already knew, and what has gone stale.

2 · The four types

Each type answers three separable questions. The original single template answered all three at once, which is why it did not stretch beyond meetings.

TypeRoutingShapeTask lines
Meeting meetings/YYYY-MM-DD-<slug>.md Decisions · Actions (with owner) · Open questions · Risks yes
Slack / email thread threads/YYYY-MM-DD-<slug>.md What was asked · What was agreed · Who owns what · Still open yes
Document or deck references/<slug>.md What it claims · Figures, each with its source locator · What could not be sourced no
Decision decisions/YYYY-MM-DD-<slug>.md Context · Options considered · What was chosen · Why · What would change it no

References are deliberately undated. Re-ingesting the same document should update the existing file rather than fork a second copy of it. The other three are events, so they carry the date they happened.

Folders are created on first use. There is nothing to set up.

3 · Why documents may not create task lines

This is the reason the feature has types at all. Tell the model to “turn every commitment into a task line” and then hand it a QBR deck, and it will produce commitments nobody made. Pulse’s scanner is deterministic, so those inventions arrive wearing an owner and a due date and look exactly as authoritative as the real ones.

So the two non-event types are told explicitly not to emit them — not left silent on the question:

“Do NOT write task lines in this file. This kind of source records what is true, not what anyone committed to, and Pulse would treat invented items as real commitments.”

A deck records claims. A decision record records a call already made. Neither is a promise, and neither should ever be nagging you three weeks later.

4 · Auto-detect

Auto-detect hands the assistant the whole routing table above and asks which row fits what you pasted.

It picks the bucket. It never picks the format. A classified paste comes out shaped identically to an explicitly-chosen one — same folder, same headings, same task-line syntax.

That line has to hold for two reasons:

  • Pulse matches literally. The scanner looks for moved: and due: exactly. Let the model improvise and it will eventually write moved on: — which does not error, it just silently stops being a tracked commitment.
  • Retrieval depends on consistency. “What did we decide about the ops email” only works when decisions always live in one place with one shape.

Two behaviours fall out of it. The assistant declares its classification in the first line of its reply, so a misfile is visible immediately rather than three weeks later. And when a paste is genuinely a toss-up between two types, it files under its best reading and parks the question in the Questions tab rather than stopping — the app’s existing pattern, reused rather than reinvented.

Pick an explicit type when you already know: a decision record that happens to read like meeting notes, for instance.

5 · Task line syntax

A commitment is a markdown task line. Pulse parses these off disk in TypeScript; the model never computes a date.

- [ ] Send the vendor the field mapping @sam moved:2026-08-01 blocked:data export due:2026-08-20
TokenRequiredMeaning
textyesWhat the commitment is
@ownernoWho holds it
moved:no, butWhen the item last moved. Without it Pulse falls back to the file’s mtime and marks the row inferred — which measures when you last touched the file, not when the work last progressed.
blocked: / needs:noWhat is holding it. Value runs to the next token, so it can contain spaces without quoting.
due:noDeadline. Overdue items sort above everything.

Tick the box to close it. Fenced code blocks are skipped by the scanner, which is why documenting this convention inside a knowledge file does not create a phantom commitment.

6 · Where the code lives

FileResponsibility
src/lib/ingest.tsThe types as data, and ingestPrompt() which renders the instruction. Same pattern as src/lib/modes.ts.
src/app/page.tsxThe Authoring write bar: selector, Ingest →, and the ? help panel.
knowledge/<assistant>/README.mdThe same conventions on the read side, so the assistant can find what it filed.

Adding a type

Append one entry to INGEST_TYPES. The selector, the prompt, and the in-app help table are all derived from that array, so nothing else needs editing.

{
  id: "spec",
  label: "Spec or requirement",
  what: "a spec — what someone asked to be built",
  file: "specs/{date}-<slug>.md",
  structure: "Requirement · Constraints · Out of scope · Acceptance",
  commitments: true,
}

The IngestId union needs the new id added alongside it. Then add the row to each knowledge-root README.md — that half is not automatic, and it is what keeps filing and retrieval in agreement.

Do not put these conventions in an assistant’s system prompt. seedAssistants() only runs when data/store.json is absent, so editing the seed changes nothing for assistants that already exist — you would be hand-editing the JSON. The knowledge-root README.md avoids this entirely, because the assistant reads its own root on every turn.

7 · Constraints

  • Writes are confined to the assistant’s own knowledge root. Every path is resolved and checked before any write. An assistant can be given a reference directory it may read but not write, and ../ escapes are refused. Logic in src/lib/scope.ts.
  • The date is computed per click, not at module load — a tab left open overnight would otherwise stamp yesterday into the filing instruction.
  • Authoring is the only mode that can write. Enforced through --allowedTools on the CLI call, not by instructing the model.
  • The instruction is text. If the assistant ignores part of it, that is a prompt problem visible in the transcript, not hidden state.
